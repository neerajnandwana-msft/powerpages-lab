# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A **Docusaurus 3.7 documentation site**, not an application. The "product" is a self-paced lab track that teaches building Microsoft Power Pages SPA sites with AI coding CLIs (Claude Code / GitHub Copilot CLI) and taking them through a full ALM lifecycle. Almost all real content is Markdown under `docs/`; `src/` holds only `css/custom.css`. The site is published to GitHub Pages.

The labs *describe* Power Pages tooling (PAC CLI, the Power Pages plugin skills/agents, Dataverse). That tooling is the subject matter — it is not used to build or test this repo.

## Commands

```bash
npm start          # local dev server with hot reload (docusaurus start)
npm run build      # production build into ./build (fails the GitHub Pages deploy if it errors)
npm run serve      # serve the built ./build locally
npm run typecheck  # tsc, the only "lint" gate — config files are .ts
npm run clear      # clear the .docusaurus cache when the dev server behaves oddly
```

There is no test runner and no ESLint. `npm run check` (typecheck → style sweep in `--check` mode → production build) is the single verification gate; `onBrokenLinks: 'throw'` means a broken internal link **fails** the build rather than warning, so a renamed lab can't silently break cross-links. Deployment is automatic: pushing to `main` triggers `.github/workflows/deploy.yml`, which runs `npm ci && npm run build` and publishes `./build` to GitHub Pages.

## Content architecture

- **Routing:** `routeBasePath` is `/`, so docs are served at the site root (no `/docs` prefix). `docs/intro.md` has `slug: /` and is the landing page.
- **Sidebar:** auto-generated from folder structure (`sidebars.ts` uses `autogenerated` per `dirName`). The four lab phases map to folders: `build/`, `integrate/`, `alm/`, plus `reference/`. Adding a Markdown file to one of these folders adds it to the sidebar automatically; order within a folder comes from each file's `sidebar_position` frontmatter.
- **URL slugs include the number prefix.** `numberPrefixParser: false` means a file like `docs/build/01-scaffold-spa-portal.md` is reachable at `/build/01-scaffold-spa-portal` (the `01-` is *not* stripped). Internal cross-links in the labs rely on this — keep the prefix when renaming and update referrers.
- **Mermaid diagrams** are enabled (`@docusaurus/theme-mermaid`) and used heavily in the labs.
- The lab track is **cumulative**: each lab starts from the portal state the previous lab produced (see the "State you carry forward" table in `docs/intro.md`). When editing a lab, keep that continuity — a change to what Lab N produces can break Lab N+1's assumptions.

## Writing style — enforced, non-obvious

Docs follow the **Microsoft Writing Style Guide**. Two equivalent scripts apply the mechanical sweeps (`scripts/ms-learn-style-sweep.mjs` for Node, `.py` for Python; same rules):

- H2/H3/H4 headings are **sentence case** (H1 / page titles are left as-is).
- `in order to` → `to`; `utilize` → `use`.
- **Don't use em dashes (`—`).** Use a colon, comma, parentheses, or separate sentences. The sweep no longer produces them; Vale's `Microsoft.Dashes` rule flags any that slip in.
- Code fences, inline code, and frontmatter are never touched.
- Brand names and acronyms keep their casing via a `PRESERVE_CASE` list in the scripts (Microsoft, Power, Dataverse, API, SPA, ALM, CSRF, etc.). **If you introduce a new product name or acronym that should not be lowercased in headings, add it to `PRESERVE_CASE` in both scripts _and_ to the Vale vocab at `.vale/styles/config/vocabularies/PowerPages/accept.txt`.**

Run the sweep after bulk doc edits. `npm run style` applies it, `npm run style:check` verifies without writing (and is what the pre-commit hook and `npm run check` use):

```bash
npm run style          # apply (alias for: node scripts/ms-learn-style-sweep.mjs docs)
```

Beyond the mechanical sweep, **Vale** enforces the rest of the Microsoft style (passive voice, wordiness, terminology, spelling) via `npm run lint:prose`. It needs the `vale` binary (`winget install errata-ai.Vale`); first run downloads the Microsoft package with `vale sync`. Vale is tuned to be _complementary_: `Microsoft.Headings` is disabled in `.vale.ini` because the mechanical sweep owns heading-case style, while `Microsoft.Dashes` is enabled to enforce the no-em-dash rule.

When writing new lab prose by hand, match this style directly rather than relying on the sweep to fix it.

The `lab-authoring` skill (`.claude/skills/lab-authoring/`) bundles all of these conventions plus the cumulative-continuity and slug rules — invoke it when adding or editing a lab.

## Frontmatter convention

Each lab `.md` starts with frontmatter like:

```yaml
---
sidebar_position: 1
sidebar_label: "Lab 01: Scaffold an SPA Portal"
title: "Lab 01: Scaffold an SPA Portal"
---
```

`sidebar_position` orders the file within its phase folder; `sidebar_label` is the sidebar text; `title` is the page `<title>` and H1 source. `docs/intro.md` additionally sets `slug: /`.
